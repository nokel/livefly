# livefly

Edit any website the way you would edit layers in a design tool. Select a region, drag it, resize it, hide it, restyle it, or write your own CSS. Your edits are saved per site and applied again on every visit, after a refresh and after closing and reopening the browser. A "Remember state" button records how you dismiss a popup so livefly can close it for you from then on.

Built for Vivaldi (and works in any Chromium browser that supports Manifest V3).

## Install in Vivaldi

1. Open `vivaldi://extensions`.
2. Turn on **Developer mode** (top right).
3. Click **Load unpacked** and choose this `livefly` folder (the one that contains `manifest.json`).
4. Pin the livefly icon to the toolbar if you like. Keyboard shortcuts can be changed at `vivaldi://extensions/shortcuts`.

Pages that were already open when you installed livefly are picked up automatically. If a page ever says it cannot be edited, reload it once.

## Using it

### Edit page

Click the livefly icon, then **Edit page** (or press `Alt+Shift+E`).

| Do this | To get this |
| --- | --- |
| Hover | Outline of the element under the cursor |
| Click | Select it |
| Drag a selected element that sits in a flex or grid row | Reorder it: the other items slide aside exactly as the site would lay them out |
| Drag a selected element anywhere else | Move it freely (it floats and nothing around it reflows). Hold `Alt` to always float |
| Drag a side or corner handle, or the edge line itself | Resize it the way the site lays things out. When the edge is shared with a neighbour in the same row, the neighbour shrinks or grows by the same amount, like a splitter. The opposite edge stays put. Hold `Shift` on a corner to keep proportions, `Alt` to resize only this element |
| `[` and `]` | Select the parent or the first child |
| Arrow keys | Nudge 1 px (`Shift` = 10 px) |
| `H` or `Delete` | Hide or show the selection |
| `Ctrl+Z`, `Ctrl+Shift+Z` | Undo and redo (100 steps) |
| `Esc` | Cancel a drag, then deselect, then close the editor |

The toolbar and the side panel float above the page and can go anywhere. Drag the toolbar by its grip on the left, or the panel by its header strip, and drag the panel's edges and corners to resize it. Double-click a grip or header to put that piece back in its default place, and the dock button snaps the panel to the other side. Positions are remembered across pages, sites and browser restarts, and they are pulled back into view if the window gets smaller.

The panel has four tabs:

- **Properties** shows the selected element: position, size, rotation, scale, opacity, colours, radius, border, shadow, font, spacing, z-index, visibility, plus a raw "Layer CSS" box. Values you changed are highlighted. Each field has a reset button.
- **Layers** shows the whole page as a tree, from `body` down, like the layers of a design tool. Every layer is named after what the site's own CSS calls it (`div#app.sidebar.r-1ihkh82`), with its test id, role or label shown beside it. Expand a layer with its arrow, point at a row to light that element up on the page exactly like hovering it (a note at the edge of the screen tells you when it is scrolled out of view), click a row to select that element, use the eye to hide or show it, and double-click a name to rename it (renames are saved per site). Edited layers carry a dot. The search box finds layers by name, class, id or label. **Edited only** switches to a list of the layers you changed, with a lock and a delete button each. **Compare with original** temporarily shows the untouched page.
- **CSS** is a free-form stylesheet for the whole site, applied live. It also shows the CSS generated by your layers.
- **Popups** manages remembered popups.

A layer can match one element ("This one") or every similar element ("All similar"), and can apply to the whole site or to the current page only. The selector is editable.

### Custom CSS without the editor

The toolbar popup has a CSS box for the current site. Changes apply live and are saved automatically. "Force !important" (on by default) makes your rules beat the site's own styles.

### Remember state

Open a popup you want gone (cookie banner, newsletter prompt, anything), click **Remember state** in the toolbar popup or the editor, then close the popup the way you normally would. livefly records the button you clicked and which elements disappeared. On later visits the popup's container is hidden by a user-origin stylesheet before the page first paints, so it never flashes, and livefly clicks the same button in the background so the site itself records the dismissal. If the popup comes back later, for example when you switch away from the window and return and the site redraws it, it stays hidden and the new button is clicked again. If the site ignores the click, page scrolling is unlocked as a fallback. It works for popups inside embedded iframes too. Per popup you can choose **Click close** or **Hide it**.

Popups that were remembered without a container (a panel rather than an overlay, such as an ad box or a "cue" card) learn it the first time livefly closes them: it notes which ancestors of the button the site removed with the click and hides that unit from then on. The Popups tab shows what is hidden for each one.

A learned container is always written relative to the popup's own button, for example `div:has(> button[data-test-id="close-cue-button"])`. It can therefore only ever match the popup that button belongs to, never a shared dialog host, a sidebar or another element that happens to use the same generated class. It is also kept small: it never grows past 35% of the window, never includes a direct child of `body`, never jumps to something many times larger than the step before it, and is skipped when the site redrew the same element instead of removing it.

Every hide selector, learned or recorded, is checked when it is loaded. Selectors that are only tag names, that rely on generated class names or ids (`.W_6LEV`, `.css-1a2b3c`), or that name a generic host (`#root`, `#modal-outer`, `.container`) are ignored, and the popup falls back to clicking its button and learning again.

Once a container is known it is collapsed with `display: none` by a user-origin stylesheet from the first paint, so the page is already in its closed layout and stays that way whether or not the click works. The hiding never depends on the click, the click limit or the timing, and it matches the redrawn popup every time the site redraws it. The click is a background courtesy so the site records the dismissal. It is repeated roughly every 300 ms and then more slowly (7 tries over about 5 seconds) until the button goes away, because some pages show a button before their click handler is attached and silently drop the first click; this is the same approach DuckDuckGo's autoconsent takes. A container learned too small (only the wrapper around the button, say) is widened the next time the popup closes, and is never narrowed.

Safety limits: a remembered popup is clicked at most 7 times per round, at most 3 rounds per element and at most 40 times per page load, and the background allows only 10 page loads per minute per popup, so a popup that keeps coming back can never trap the page in a reload loop. When a limit stops the clicking, the container is still hidden. Automatic clicks on links never navigate away.

After you change livefly's files, reload the extension on the browser's extensions page, then refresh the page. A page refresh alone loads the new page scripts but keeps the old background script, and livefly shows a banner when it notices that mismatch.

### If something looks wrong

- **Pause edits on this site**: untick "Apply my edits on this site" in the toolbar popup, or press `Alt+Shift+P`.
- **Pause everything**: options page, "Pause livefly everywhere".
- **Reset a site**: "Reset this site" in the toolbar popup.
- **Back up or move your edits**: click the livefly icon, then **Export saved changes**. It saves one file, `livefly-saved-changes-<date>.json`, with every site you edited (edits, custom CSS, remembered popups and layer names). It is a single plain text file, so no zip is needed. To restore it, or to copy your edits to another browser or computer, click the icon, then **Import changes** and pick that file. Both buttons work on any page, including `vivaldi://` pages, and the same two buttons are on the options page. Importing replaces the saved changes of the sites in the file and leaves every other site alone. A file that is not a livefly export is refused with a message and nothing is changed.

## How it avoids breaking websites

The design follows what uBlock Origin does for cosmetic filtering. The sources in the [uBlock Origin repository](https://github.com/gorhill/uBlock) (`platform/common/vapi-client.js`, `src/js/contentscript.js`, `src/js/scriptlets/epicker.js`) were read to model these choices:

- **Nothing in the page is touched.** Edits are injected as user-origin stylesheets by the extension (`scripting.insertCSS` with `origin: "USER"`). They add no `<style>` or `<link>` to the page, add no attributes or inline styles, and do not appear in `document.styleSheets`. The page cannot see them, remove them, or detect them with a MutationObserver. This is verified in the end-to-end tests.
- **Elements are never removed.** Hiding uses `display: none !important`, and moving uses the individual CSS `translate` property, which composes with the site's own `transform` instead of replacing it and does not reflow neighbours.
- **User-origin `!important` outranks every author style**, including the site's own `!important` rules and inline `!important` styles, with no specificity games.
- **No flash of the original page.** The content script runs at `document_start`; a temporary constructed stylesheet bridges the few milliseconds until the user-origin sheet is in place, then removes itself.
- **One bad rule cannot break the rest.** Each selector gets its own CSS rule, custom CSS goes in its own stylesheet, and every selector and value is validated (no `{`, `}`, `;` injection, balanced brackets and quotes). Rules that would hide `html` or `body` are neutralised.
- **Stable selectors.** The selector generator prefers ids and test attributes, filters out generated class names (CSS-in-JS and CSS-modules hashes, state classes), verifies uniqueness, and only falls back to `nth-of-type` as a last resort (the same preference uBlock Origin has).
- **Isolated editor UI.** The editor lives in a closed shadow root appended to `<html>` (not `<body>`, so frameworks that manage the body never see it). Its styles use constructed stylesheets and CSSOM, so strict Content-Security-Policy pages work. While editing, clicks and keys are captured so the page does not react to them, and nothing is left behind afterwards.
- **Cheap and quiet.** No observers run on pages where you have no popup rules. When they do, they are throttled with a short timer. The timer does not wait for a repaint, because browsers pause painting while a window is covered or minimised.
- **Fails safe.** If the extension is reloaded, orphaned scripts stop quietly.

## Limitations

- Edits change appearance only. Changing text or removing nodes from the DOM is deliberately not offered because it is the main way tools break sites.
- Pixel sizes and offsets are absolute. A layout that changes a lot with window width may need a second pass at another width, or a CSS media query in the CSS tab.
- Resizing is flow-aware for flex rows and block layouts. Grid tracks are not rewritten, so an item in a grid row is resized on its own.
- Reordering works through the CSS `order` property, so it only applies to flex and grid containers.
- The editor works on the top page. An iframe can be selected, moved and hidden as a whole, but its inside is not editable. Popups inside iframes can be remembered.
- Elements inside shadow DOM can only be edited as a whole (their host element).
- Selectors can stop matching if a site redesigns its markup. The Layers tab shows a match count per layer, and a warning when it is zero, so you can fix the selector.
- Sites are keyed by hostname without `www.`. `example.com` and `www.example.com` share edits; `shop.example.com` has its own.

## Permissions

- `storage`, `unlimitedStorage`: save your edits locally. Nothing is sent anywhere.
- `scripting`: inject the edit stylesheets and, on demand, the editor.
- Access to all http and https sites: needed to apply your edits automatically on the sites you choose. livefly makes no network requests of its own.

## Files

| File | Purpose |
| --- | --- |
| `manifest.json` | Manifest V3 definition |
| `background.js` | Service worker: injects and removes stylesheets, serialises storage writes, popup click rate limit, commands |
| `shared.js` | Data model, validation and the rules-to-CSS compiler (also used by the tests) |
| `dom.js` | Selector generation and DOM helpers |
| `content.js` | Runs at `document_start` in every frame: loads the site's edits and keeps the page's stylesheets in sync |
| `popups.js` | Popup recorder and auto-close watcher |
| `backup.js` | Export and import of saved changes, shared by the toolbar popup and the options page |
| `editor.js` | The visual editor, injected only when you open it |
| `popup/`, `options/` | Toolbar popup and options page |
| `tests/` | Unit tests and a browser end-to-end suite |

## Tests

Unit tests (no dependencies, pure logic):

```
node --test tests/unit.test.js
```

End-to-end tests (91 checks) launch a separate Vivaldi instance with a throwaway profile, load the extension and drive it with real mouse and keyboard input over the DevTools protocol. They do not touch your normal Vivaldi profile or windows. Requires Node 22 or newer.

```
node tests/e2e.js
```

Set `LIVEFLY_BROWSER` to the path of another Chromium-based browser to test with it. The `tests` folder is not needed to run the extension and can be deleted.
